### 修复：废止版本降权（2026-09-13）

`documents.status`（active / deprecated）**显式标记**废止状态——不靠"版本号最大即现行"推断，
因为只召回到旧版本时那种推断会直接失效，而这正是要防的事故。

检索时对 `deprecated` 切片加距离惩罚后重排：

```python
apply_version_penalty(chunks, rag_deprecated_penalty)   # 默认 0.15
```

**降权而不是过滤**：过滤能让指标立刻变漂亮，但会彻底查不到历史条款；
降权保留可追溯性，只是不再让废止版本抢在现行版本前面。
原始 `distance` 不变（拒答阈值与分析依赖它），只新增 `penalized_distance` 用于排序；
候选多取 `rag_oversample` 倍，避免降权后现行版本掉出 top_k。

### 扫参结果（同一评测集，20 题）

| penalty | recall@5 | version | refuse | 失败数 |
| --- | --- | --- | --- | --- |
| 0（修复前） | 0.975 | **0.75** | 1.0 | 5 |
| 0.05 | 0.975 | 1.0 | 1.0 | 1 |
| **0.15（采用）** | **1.0** | **1.0** | 1.0 | **0** |
| 0.3 | 1.0 | 1.0 | 1.0 | 0 |
| 0.6 | 1.0 | 1.0 | 1.0 | 0 |

效果从 0.05 起生效，在 0.1–0.6 区间稳定，**不是卡在某一个巧合值上**。

### 修复的代价（必须知道）

问"旧版本制度中旗舰设备保修多久"时，top5 全是 V2.0，**V1.1 没进来**——
语义检索不理解"旧版本"这个意图，惩罚又把它往后推。
降权确实保留了可追溯性（另一例中 V1.1 原始距离最小、被压到第 5 但仍在前 5），
但代价是：**用户明确想查旧版本时，会变难。** 这需要在评测集里补这类题来量化。

### 扩大评测集后：满分消失，真问题浮出来（2026-09-13）

评测集从 20 题扩到 **48 题**，新增三类：改写问法、明确查旧版本（已知盲区）、
"看起来相关其实库里没有"的拒答题。结果：

```
recall_at_k        0.9375   （原 1.0）
version_accuracy   0.9231   （原 1.0）
refuse_accuracy    0.9167   （原 1.0）
failures           7 / 48   （原 0 / 20）
```

**满分是评测集太小造成的错觉，不是系统真的没问题。** 扩大后暴露出两个真问题：

#### 问题一：查旧版本 3/3 全败（已知盲区被量化）

`hist-v11-*` 三题期望召回 V1.1，实际 top1 全是 V2.0，证据召回率 0%。
这是上一轮"降权代价"的量化结果：语义检索不理解"旧版本"这个意图，
惩罚又把它往后推。**要修得靠查询理解或元数据过滤，不是继续调惩罚系数。**

#### 问题二：拒答阈值存在不可约错误

top1 距离分布：

| 类别 | 最小 | 中位 | 最大 |
| --- | --- | --- | --- |
| direct | 0.1792 | 0.2341 | 0.4092 |
| version_trap | 0.1975 | 0.2536 | 0.4133 |
| cross_section | 0.2239 | 0.2986 | 0.3279 |
| paraphrase | 0.2643 | 0.3416 | **0.4520** |
| **should_refuse** | **0.3576** | 0.5305 | 0.7817 |

两类分布**重叠**：最远的有答案题 0.4520，最近的应拒答题 0.3576。
阈值扫描（离线模拟，不重跑模型）：

| 阈值 | 拒答正确率 | 误拒（有答案却被拒） | 总失败 |
| --- | --- | --- | --- |
| 0.35 | 1.00 | 6 | 6 |
| 0.42 | 0.78 | 1 | 3 |
| **0.46** | 0.78 | **0** | **2** |
| 0.50（当前） | 0.56 | 0 | 4 |

理论上 0.46 优于当前的 0.50，但**最优点的裕度只有 0.01**
（0.4520 的有答案题 vs 0.4617 的应拒答题），这属于拟合噪声，不是稳健改进。
**结论：阈值法在这个 embedding 上有约 2/9 的不可约错误，继续调参没有意义，
要改善必须换方法**（相关性重排打分、或要求回答必须有引用支撑）。

#### 一个重要的补充发现：拒答有两道防线

上面 4 道"漏拒"（阈值没拦住、走了生成路径）的题，端到端回答是：

```
Q: 过了保修期维修要多少钱？
   refused=false（检索层判定失败），但回答：
   "当前资料中没有找到依据。现有资料仅列出了不享受免费保修的情形…
    未提供具体的有偿维修收费标准或金额。"  引用数 = 0
```

**后端阈值漏了，提示词约束接住了，且没有伪造引用。**
所以检索层的 `refuse_accuracy` 比端到端行为更严格，读这个数字时要注意它衡量的
是"第一道防线"，不等于系统的最终表现。

### 基线数字（修复前，20 题，top_k=5）

```
recall_at_k        0.975
version_accuracy   0.75     ← 问题在这里
refuse_accuracy    1.0
citation_accuracy  1.0
failures           5 / 20
```

**version_accuracy 0.75 是本项目当前最重要的数字**：20 道题里有 5 道的 top1 命中了
已废止的 V1.1（第三方配件、15 天换货、紧急故障、重要故障、跨段题）。
这就是"过期政策被错误引用"被量化的结果——之前只是"感觉有风险"，现在是 25% 的失败率。
后面任何版本过滤或元数据加权的改动，都应该拿这个数字来证明有没有变好。

已知指标缺陷：citation_accuracy 目前只要求"至少引用到一条正确证据"，
不惩罚"同时引用了废止版本"，因此 1.0 偏乐观；后续应补"引用纯净度"。

## 四、已复现的关键问题（真实实测，非模拟）

纯向量检索下（余弦距离，越小越近）：

```
Q: 紧急故障多久到现场？
   V1.1  d=0.2586   ← 已废止版本排第一（错误召回）
   V2.0  d=0.2634

Q: 旗舰型设备整机保修多久？
   V2.0  d=0.1801
   V1.1  d=0.1839   ← 与现行版本仅差 0.0038
```

**结论**：向量检索无法区分文档版本，过期政策会被同等甚至优先召回。
这是后续版本过滤/元数据加权要解决的问题，也是评测集必须覆盖的题型。

### 接上生成后的实测（2026-09-13）

```
Q: 紧急故障多久到现场？
   应答 4 小时（现行 V2.0）——答对了
   但引用顺序里 V1.1 排第一，模型是靠"版本冲突对照表"[25] 恰好也被召回，
   才自己读出差异的
```

**这次答对是运气，不是机制。** 如果冲突对照表没进 top_k，模型很可能直接引用 V1.1 的 6 小时。
所以版本问题并没有被解决，只是被"资料里恰好有一张对照表"掩盖了——
必须靠评测集把它暴露成可量化的失败率，再用版本过滤去修。
