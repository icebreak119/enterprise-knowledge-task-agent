# RAG 项目流程与进度

> 最后更新：2026-09-13（提交 `d3a9bce`）

这个项目有两条链路：**离线入库**把文档变成可检索的向量，**在线问答**把用户问题变成有依据的回答。
下面按实际执行顺序梳理，并标出当前位置。

### 基线数字（2026-09-13，20 题，top_k=5）

```
recall_at_k        0.975
version_accuracy   0.75     ← 问题在这里
refuse_accuracy    1.0
citation_accuracy  1.0
failures           5 / 20
```

**version_accuracy 0.75 是本项目当前最重要的数字**：20 道题里有 5 道的 top1 命中了
已废止的 V1.1（第三方配件、15 天换货、紧急故障、重要故障、跨段题）。
这就是"过期政策被错误引用"被量化的结果——之前只是"感觉有风险"，现在是 25% 的失败率。
后面任何版本过滤或元数据加权的改动，都应该拿这个数字来证明有没有变好。

已知指标缺陷：citation_accuracy 目前只要求"至少引用到一条正确证据"，
不惩罚"同时引用了废止版本"，因此 1.0 偏乐观；后续应补"引用纯净度"。

## 四、已复现的关键问题（真实实测，非模拟）

纯向量检索下（余弦距离，越小越近）：

```
Q: 紧急故障多久到现场？
   V1.1  d=0.2586   ← 已废止版本排第一（错误召回）
   V2.0  d=0.2634

Q: 旗舰型设备整机保修多久？
   V2.0  d=0.1801
   V1.1  d=0.1839   ← 与现行版本仅差 0.0038
```

**结论**：向量检索无法区分文档版本，过期政策会被同等甚至优先召回。
这是后续版本过滤/元数据加权要解决的问题，也是评测集必须覆盖的题型。

### 接上生成后的实测（2026-09-13）

```
Q: 紧急故障多久到现场？
   应答 4 小时（现行 V2.0）——答对了
   但引用顺序里 V1.1 排第一，模型是靠"版本冲突对照表"[25] 恰好也被召回，
   才自己读出差异的
```

**这次答对是运气，不是机制。** 如果冲突对照表没进 top_k，模型很可能直接引用 V1.1 的 6 小时。
所以版本问题并没有被解决，只是被"资料里恰好有一张对照表"掩盖了——
必须靠评测集把它暴露成可量化的失败率，再用版本过滤去修。
